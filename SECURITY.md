# Security Policy

## Reporting a vulnerability

Email **security@unabyss.com**. Please do not open a public issue for a
security report.

Include what you need to describe the problem — affected version, what
you did, what happened — and a way to reach you. If you would rather
encrypt the report, say so in a first message and we will arrange it.

We aim to acknowledge a report within **3 business days** and to tell
you what we intend to do about it, and when, once we have reproduced it.
We will keep you updated while a fix is in progress and will credit you
when it ships, unless you would rather we did not.

We are grateful to researchers who help keep Unabyss safe and will work
with you in good faith. We do not run a paid bug bounty.

## Scope

This policy covers the Unabyss plugin for Obsidian in this repository. Vulnerabilities in
the hosted Unabyss service, in the web application or in the MCP server
go to the same address — say which one you mean and we will route it.

Third-party dependencies are in scope only where this component's own
use of them is what creates the problem; otherwise please report to the
upstream project and tell us, so we can pick up the update.

## What happens next

Reports are triaged under Onetype P.S.A.'s incident response process.
Where a vulnerability in this component turns out to be actively
exploited, or where an incident affects its security, we additionally
report to the competent authorities within the timescales set by
Regulation (EU) 2024/2847 (the Cyber Resilience Act), and we inform
affected users.

## Supported versions

The latest released version is the supported one. Fixes are shipped as a
new release rather than backported, and the release notes say what was
fixed.
